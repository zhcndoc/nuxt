AI 助手正日益成为开发者体验中不可或缺的一部分。为了帮助它们提供关于 Nuxt 的准确且最新的信息，我们构建了一个 MCP 服务器，以结构化的方式公开我们的文档、博客文章和部署指南。以下是我们如何使用 [Nuxt MCP Toolkit](https://mcp-toolkit.nuxt.dev) 来实现这一目标，以及你如何能构建自己的 MCP 服务器。

::callout{icon="i-lucide-bot"}
想要试用 Nuxt MCP 服务器？跳转到 [Nuxt MCP 服务器文档](/docs/4.x/guide/ai/mcp)。
::

## 什么是 MCP，以及为什么我们要构建它？

[模型上下文协议（Model Context Protocol，MCP）](https://modelcontextprotocol.io/) 是一个开放标准，允许 AI 助手安全地访问数据和工具。你可以将其视为专为 AI 助手设计的 API：它不是返回 HTML 或通用 JSON，而是提供结构化且语义化的数据，便于大型语言模型（LLMs）轻松理解和使用。

MCP 定义了三种主要原语：

- **资源（Resources）**：允许服务器共享为语言模型提供上下文的数据，如文件、数据库模式或应用特定信息。每个资源通过唯一 URI 标识。
- **工具（Tools）**：使 AI 模型能够与外部系统交互并执行操作（例如搜索或 API 调用）
- **提示（Prompts）**：可复用的提示模板，带参数，供用户调用

### 为什么选择 MCP 而非 RAG？

我们观察到，使用 MCP 服务器的 AI 助手相比传统的 RAG（检索增强生成）方法，能够提供**显著更好的响应**：

- **输入输出皆为结构化数据**：工具接受定义良好的参数，返回类型化数据，有效避免幻觉
- **可组合的工具**：AI 助手可以将多个工具串联使用，使用一个工具的输出作为另一个工具的输入（例如先搜索主题，再获取完整内容）
- **速度更快且更精准**：无需在查询时处理和拆分大型文档
- **始终保持最新**：直接访问内容层，无需重新索引
- **上下文感知导航**：AI 能够智能地在内容之间导航关系

现在，[Nuxt](https://nuxt.com/mcp) 和 [Nuxt UI](https://ui.nuxt.com/mcp) 都拥有类似架构的 MCP 服务器，使 AI 助手更轻松地帮助开发者使用这些框架。

## 技术架构

我们的 MCP 服务器直接内置于 nuxt.com，使用了 [Nuxt MCP Toolkit](https://mcp-toolkit.nuxt.dev) 模块。该模块自动从服务器目录发现工具、资源和提示：

```
nuxt.com/
├── server/
│   └── mcp/
│       ├── tools/
│       │   ├── docs/
│       │   │   ├── list-documentation-pages.ts
│       │   │   ├── get-documentation-page.ts
│       │   │   └── ...
│       │   ├── blog/
│       │   ├── modules/
│       │   └── ...
│       ├── resources/
│       │   ├── docs/
│       │   │   └── nuxt-documentation-pages.ts
│       │   └── ...
│       └── prompts/
│           ├── docs/
│           │   └── find-documentation-for-topic.ts
│           └── ...
└── nuxt.config.ts
```

架构十分简单：你只需将工具、资源和提示定义为独立文件，模块会自动注册它们并公开一个 HTTP 端点供 MCP 客户端连接。无需手动设置服务器或配置传输，只需在正确目录中创建文件，即可立即使用。`tools/docs/` 这样的子目录是可选的，仅用于整理文件；工具名称仍由文件名决定。

## 实现深度解析

### 模块设置

入门只需将模块添加到 Nuxt 配置中：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxtjs/mcp-toolkit'],
  mcp: {
    name: 'Nuxt',
  }
})
```

就这么简单。模块会自动扫描你的 `server/mcp/` 目录并注册发现的内容。

### 工具：提供给 AI 模型的操作

工具使语言模型可以通过接受参数并执行操作与外部系统交互。以下是 `list_documentation_pages` 工具的简化示例：

```ts [server/mcp/tools/docs/list-documentation-pages.ts]
import { z } from 'zod'
import { queryCollection } from '@nuxt/content/server'

export default defineMcpTool({
  description: `Lists Nuxt documentation pages, optionally filtered by search term.

WHEN TO USE: When you need to find documentation about a topic but don't know the exact page path.
WHEN NOT TO USE: If you already know the page path, use get_documentation_page directly.`,
  inputSchema: {
    version: z.enum(['3.x', '4.x']).optional().default('4.x').describe('Documentation version to fetch'),
    search: z.string().optional().describe('Filter pages by keyword (matches title, path, and description)')
  },
  annotations: {
    readOnlyHint: true,
    openWorldHint: false
  },
  cache: '1h',
  async handler({ version, search }) {
    const event = useEvent()

    let docs = await queryCollection(event, version === '3.x' ? 'docsv3' : 'docsv4')
      .select('title', 'path', 'description')
      .all()

    if (search) {
      const terms = search.toLowerCase().split(/\s+/)
      docs = docs.filter((doc) => {
        const haystack = `${doc.title} ${doc.path} ${doc.description}`.toLowerCase()
        return terms.every(term => haystack.includes(term))
      })
    }

    return docs.map(doc => ({
      title: doc.title,
      path: doc.path,
      description: doc.description,
      url: `https://nuxt.com${doc.path}`
    }))
  }
})
```

请留意以下关键点：
- **`defineMcpTool`** 会被自动导入，无需手动导入
- **`inputSchema`** 使用 Zod 进行参数验证
- **`annotations`** 会告知客户端该工具只读取数据，因此可以在无需确认的情况下调用
- **`cache: '1h'`** 启用内置响应缓存
- **处理函数直接返回数据**：数组和对象会自动序列化为 JSON，字符串则作为文本发送。若要报告失败，请抛出错误（例如使用 `createError()`），而不是返回错误对象。

[线上工具](https://github.com/nuxt/nuxt.com/blob/main/server/mcp/tools/docs/list-documentation-pages.ts)功能更多：它还支持 Nuxt 5、同时搜索所有版本、包含 CLI 和示例页面，并且只在提供搜索词时返回描述，以缩小响应内容。

工具名称会自动从文件名派生（`list-documentation-pages.ts` 会变为 `list_documentation_pages`）。

### 资源：为语言模型提供上下文

资源允许服务器共享给予语言模型上下文的数据，比如文件、数据库结构或应用特定信息。每个资源都有唯一 URI 识别。

暴露文件的最简单方式是使用 `file` 属性，它自动处理 URI 生成、MIME 类型检测和文件读取：

```ts [server/mcp/resources/readme.ts]
export default defineMcpResource({
  name: 'readme',
  description: '项目 README 文件',
  file: 'README.md' // 相对于项目根目录
})
```

对于动态资源，可以使用自定义处理函数：

```ts [server/mcp/resources/docs/nuxt-documentation-pages.ts]
import { queryCollection } from '@nuxt/content/server'

export default defineMcpResource({
  uri: 'resource://nuxt-com/documentation-pages',
  description: '完整的 Nuxt 文档页面列表（默认为 v4.x）',
  cache: '1h',
  async handler(uri: URL) {
    const event = useEvent()

    const allDocs = await queryCollection(event, 'docsv4')
      .select('title', 'path', 'description')
      .all()

    const result = allDocs.map(doc => ({
      title: doc.title,
      path: doc.path,
      description: doc.description,
      version: '4.x',
      url: `https://nuxt.com${doc.path}`
    }))

    return {
      contents: [{
        uri: uri.href,
        mimeType: 'application/json',
        text: JSON.stringify(result, null, 2)
      }]
    }
  }
})
```

与工具不同，资源由应用驱动，宿主应用会根据用户需求决定如何整合它们，例如通过显式选择的 UI 元素或自动包含上下文。

### 提示：可复用模板

提示是带参数的可复用模板，用户调用后返回对话格式，引导 AI 执行具体工作流程：

```ts [server/mcp/prompts/docs/find-documentation-for-topic.ts]
import { z } from 'zod'
import { queryCollection } from '@nuxt/content/server'

export default defineMcpPrompt({
  description: '查找特定主题或功能的最佳 Nuxt 文档',
  inputSchema: {
    topic: z.string().describe('描述你想了解的内容'),
    version: z.enum(['3.x', '4.x']).optional().describe('要搜索的文档版本')
  },
  async handler({ topic, version = '4.x' }) {
    const event = useEvent()
    const docsVersion = version === '4.x' ? 'docsv4' : 'docsv3'

    const allDocs = await queryCollection(event, docsVersion)
      .select('title', 'path', 'description')
      .all()

    const allPages = allDocs?.map(doc => ({
      title: doc.title,
      path: doc.path,
      description: doc.description,
      url: `https://nuxt.com${doc.path}`
    })) || []

    return {
      messages: [{
        role: 'user' as const,
        content: {
          type: 'text' as const,
          text: `帮我找到这个主题的最佳 Nuxt 文档："${topic}"。以下是所有可用的文档页面：${JSON.stringify(allPages, null, 2)}`
        }
      }]
    }
  }
})
```

提示与工具不同：提示由用户调用并返回对话消息；工具由模型控制，返回结构化数据。

### 内置助手函数

该模块提供了若干自动导入的助手函数以简化常见模式：

- **`defineMcpTool`**、**`defineMcpResource`**、**`defineMcpPrompt`**：定义你的 MCP 原语
- **`imageResult(data, mimeType)`** 和 **`audioResult(data, mimeType)`**：从工具返回 Base64 编码的媒体

::note
模块早期版本使用 `jsonResult()`、`textResult()` 和 `errorResult()` 来组织工具响应。这些函数仍可使用，但已弃用：请直接从处理函数返回值，并通过抛出错误来报告失败。
::

### 使用 Nuxt 服务器工具函数

在处理函数中使用如 `useEvent()` 等 Nuxt 服务器工具，需要在 Nuxt 配置中启用 `asyncContext`：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    asyncContext: true
  }
})
```

然后即可访问 H3 事件，并使用来自 [Nuxt Content](https://content.nuxt.com) 的 `queryCollection` 等 Nuxt 服务器组合式函数。

## 构建你自己的 MCP 服务器

准备为你自己的应用构建 MCP 服务器了吗？借助 Nuxt MCP Toolkit，只需几分钟即可完成。

### 1. 安装模块

```bash [Terminal]
npx nuxt add mcp
```

您也可以手动安装模块，以及用于参数验证的 Zod：

```bash [Terminal]
npm install -D @nuxtjs/mcp-toolkit zod
```

### 2. 配置模块

向 Nuxt 配置添加基础配置：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxtjs/mcp-toolkit'],
  mcp: {
    name: 'my-app',
    version: '1.0.0'
  }
})
```

### 3. 创建你的第一个工具

在 `server/mcp/tools/` 下创建文件：

```ts [server/mcp/tools/search.ts]
import { z } from 'zod'

export default defineMcpTool({
  description: '搜索我的内容',
  inputSchema: {
    query: z.string().describe('搜索查询')
  },
  async handler({ query }) {
    // 你的搜索逻辑
    return await searchContent(query)
  }
})
```

就这样！你的 MCP 服务器现在可通过 `https://your-domain.com/mcp` 访问。

### 4. 添加资源和提示（可选）

你也可以按照同样的模式添加资源和提示：

```ts [server/mcp/resources/readme.ts]
export default defineMcpResource({
  name: 'readme',
  description: '项目 README 文件',
  file: 'README.md'
})
```

有关更高级的配置选项，请查看 [Nuxt MCP Toolkit 文档](https://mcp-toolkit.nuxt.dev)。

### 其他 AI 助手

Nuxt MCP 服务器支持 Claude Desktop、Windsurf、Visual Studio Code、ChatGPT 及诸多其他兼容 MCP 的 AI 助手。有关所有平台的完整设置说明，请查阅我们的 [MCP 文档](/docs/4.x/guide/ai/mcp)。

### 仅公开需要的工具

AI 助手可见的每个工具都会占用上下文空间。如果只需要服务器的一部分，可以通过 `X-MCP-Tools` 请求头传入以逗号分隔的工具名称，服务器就只会公开这些工具：

```json [.cursor/mcp.json]
{
  "mcpServers": {
    "nuxt": {
      "type": "http",
      "url": "https://nuxt.com/mcp",
      "headers": {
        "X-MCP-Tools": "list_documentation_pages,get_documentation_page"
      }
    }
  }
}
```

服务器会拒绝未知的工具名称，因此拼写错误会明确报错，而不是悄悄隐藏工具。[MCP 文档](/docs/4.x/guide/ai/mcp)列出了所有可用工具。

这是 Nuxt MCP Toolkit 提供的功能，因此任何使用该模块构建的服务器也都支持。
